- **Wireframe:** סקיצות ASCII בכיוון RTL — צד ימין של הסקיצה הוא תחילת המסך (start). אייקונים מסומנים בסוגריים מרובעים.
- **רכיבים:** בשם הקובץ הממומש כשקיים; רכיב חדש של 1.1 מסומן «חדש 1.1».
- **מצבים:** לכל מסך שישה מצבי מערכת לפחות: Loading / Empty / Error / Offline / Success (+ מצב "החנות כבויה" — הדגלים השכבתיים, פרק 2.6 במסמך האב: מה שכבוי אינו קיים בעמוד, לא "מנוטרל").
- **אנליטיקה:** אירועים אך ורק מסט פרק 24 במסמך האב (`product_viewed` … `order_completed`); מסכי ניהול — ללא אירועי לקוח, תיעוד audit בלבד.
- **נגישות:** ת״י 5568 מחייב (פרק 21); כאן מפורט רק מה שספציפי למסך.

## מה חדש בגרסה 1.1 (מסומן «עדכון 1.1» בגוף המסמך)

1. אייקון **"שמורים"** בכותרת האתר; סימון מועדף כ**אייקון ספר** במקום לב; עמוד ציבורי **"הספרים שאהבתי"** (מסך 1).
2. שדה **קופון כבר בעמוד העגלה**, עם הצגת ההנחה בסיכום (מסך 3).
3. התחברות: **OTP לטלפון או מייל+סיסמה — לבחירת המשתמש** (מסך 7; מעדכן את פרק 4.4 במסמך האב — טעון עדכון מקביל שם).
4. מלאי **רב־מחסני** — עמודת "מיקום" ותנועות פר מיקום (מסך 10).
5. קופונים — שדה **"ניתן לשילוב עם קופונים נוספים"**, ברירת מחדל: לא (מסך 12).
6. **הגדרות חנות** עוברות ללשונית "חנות" בניווט הניהול — לא תחת "ספרים" (מסך 14).
7. מסך **ניהול צוות והרשאות** — חמישה תפקידים, הזמנה במייל וסיסמה ראשונית (מסך 15).

## מסך 1: נקודות כניסה — קטלוג, עמוד ספר וכותרת האתר

### Wireframe


### מבנה והיררכיה
- הכותרת: ניווט קיים ← אזור פעולות בקצה השמאלי (end): **אייקון שמורים («עדכון 1.1»)** ואחריו מונה הסל, ואז מתג שפה. המונה badge בורדו על אייקון הסל.
- כרטיס קטלוג: כריכה → שם → מחבר → מחיר (מבצע: מחיר רגיל מחוק + מחיר מבצע בולט). כפתור סימון בפינת ה־end העליונה של הכריכה.
- עמוד ספר: המחיר והכפתור החי יושבים ב־Hero בלבד; ה־CTA הסופי, ה־StickyNav וה־FloatingActions מפנים לאותה פעולה (רכיב אחד, פרק 2.1 במסמך האב).

### רכיבים
`SiteHeaderClient` (+`CartIndicator`), `BookCard` (+`FavouriteButton`), `BookHeroActions`, `BookFinalCta`, `FloatingActions`, `AddToCartButton` (וריאנטים `solid`/`quiet`), `getEffectivePrice`/`formatPrice` מ־`src/lib/commerce/pricing.ts`. «חדש 1.1»: `SavedIndicator` (אייקון שמורים בכותרת), עמוד `/[locale]/favourites`.

### פעולות
- הוספה לסל (`cart.add`, מקסימום 99) → Toast + עדכון מונה; בקטלוג Toast בלבד (לא לקטוע סינון), בעמוד ספר מותר לפתוח Mini Cart.
- סימון/הסרת שמור — «עדכון 1.1»: האייקון הוא **ספר** (קווי → מלא בעת סימון), לא לב; אותה אנימציית spring קיימת. לחיצה על אייקון השמורים בכותרת → עמוד "הספרים שאהבתי".
- בעמוד "הספרים שאהבתי": הוספה לסל פר כרטיס, הסרה מהשמורים, "הוספת כל הרשימה לסל" (מדלגת על שאזל ומדווחת).

### מובייל מול דסקטופ
- מובייל: כפתור השמירה על הכרטיס גלוי תמיד (אין hover); בדסקטופ נחשף ב־hover/focus (התנהגות `FavouriteButton` הקיימת). עמוד השמורים: רשת 2 עמודות במובייל, 4 בדסקטופ.
- ה־FloatingActions (מובייל) כולל הוספה לסל ישירה כשהעגלה פעילה.

### RTL
מאפיינים לוגיים בלבד (`end-3`, `ms-*`); ה־badge של המונה ב־`-end-0.5`. מחיר בספרות — `tabular-nums`; אין `dir=ltr` על מחירים (₪ מוצג בפורמט he-IL). אייקון הסל אינו מהופך.

### מצבים
- **חנות כבויה** (`cart_enabled=false`): אין כפתורי סל, אין מונה — הרכיבים אינם מרונדרים. אייקון השמורים («1.1») מוצג גם כשהחנות כבויה — שמורים אינם פיצ׳ר מסחר.
- **אזל:** הכפתור disabled עם "אזל מן המלאי"; **הזמנה מוקדמת:** "הזמנה מראש". **Loading:** אין — הזמינות מגיעה מהשרת עם העמוד. **Offline:** ההוספה מקומית ופועלת; אימות המחיר יידחה. **Empty (עמוד שמורים):** ריק + CTA לקטלוג. **Success:** Toast "‎{title} נוסף לסל".

### טקסטים
- קיימים (`books`): "הוספה לסל", "הזמנה מראש", "אזל מן המלאי", "הוספה למועדפים"/"הסרה מהמועדפים", aria: "הוספת {title} למועדפים".
- קיימים (`store`): Toast "‎{title} נוסף לסל"; aria למונה: "סל הקניות, # פריטים".
- «מוצע 1.1»: כותרת העמוד "הספרים שאהבתי"; aria לאייקון הכותרת "הספרים שאהבתי, {count} ספרים"; ריק: "עוד לא סימנתם ספרים. לחיצה על אייקון הספר בכרטיס — והוא יישמר כאן."; כפתור "הוספת כל הרשימה לסל"; עדכון מפתחות `favouriteAdd/Remove` ל"שמירה למדף שלי"/"הסרה מהשמורים".

### דביקות וגלילה
הכותרת דביקה (קיים); המונה מתעדכן בלי קפיצת layout (רוחב מינימלי קבוע). `StickyNav` בעמוד ספר גולל אל ה־Hero — שם הכפתור החי.

### נגישות ומקלדת
- מונה הסל: `aria-label` דינמי (plural מלא); ה־badge עצמו `aria-hidden`.
- כפתור השמירה: `aria-pressed`, נחשף גם ב־`focus-within` (קיים); בעמוד שמורים — מחיקה מחזירה פוקוס לכרטיס הבא.
- Toast באזור `aria-live="polite"` גלובלי (ב־`CartProvider`) — הכרזה בלי הזזת פוקוס.

### אנליטיקה
`product_viewed` (טעינת עמוד ספר), `product_saved` (סימון שמור), `product_added_to_cart` (כל נקודות ההוספה).

### קריטריוני קבלה
1. בכל עמוד ציבורי מוצג מונה סל אחד בלבד, מתעדכן תוך ≤100ms מהוספה (מצב מקומי, בלי קריאת שרת).
2. אייקון השמורים והמונה מיושרים לקצה ה־end בכל רוחב מסך; אין גלישת layout כשהמונה עולה מ־9 ל־10.
3. אפס רכיבים המציגים מחיר מלבד אלה הצורכים `getEffectivePrice` (ביקורת קוד; grep על `Intl.NumberFormat` בתיקיות ה־UI ריק).
4. סימון שמור עובד ללא חשבון ושורד רענון (localStorage `kr:favourites`), ומוצג בעמוד "הספרים שאהבתי" מיד.
5. במבצע מוצגים שני המחירים — הרגיל ב־`<s>` — וההפרש אינו מחושב בצד הלקוח.
6. ניווט מקלדת: Tab מגיע לאייקון שמורים → סל → שפה בסדר הזה; Enter על כל אחד מפעיל.

## מסך 2: Mini Cart — מגירת הסל

### Wireframe

```
                              ┌──────────── מגירה (end) ─┐
 (רקע מוכהה — לחיצה סוגרת)    │ [×] סגירת הסל   סל הקניות │
                              ├───────────────────────────┤
                              │ [כריכה] שם הספר           │
                              │  ₪89   [−] 1 [+]  הסרה   │
                              │ ───────────────────────── │
                              │ [כריכה] ספר שאזל          │
                              │  "אזל מהמלאי — הוסר…"     │
                              ├───────────────────────────┤
                              │ ▓▓▓▓▓░░░ עוד ₪41 למשלוח… │
                              │ יגיע עד יום שלישי, 18.8   │
                              ├───────────────────────────┤
                              │ סכום ביניים        ₪178  │
                              │ [ לצפייה בסל ][ מעבר     │
                              │                לתשלום ]  │
                              └───────────────────────────┘
```

### מבנה והיררכיה
כותרת המגירה ("סל הקניות") + כפתור סגירה ראשון בטאב → רשימת שורות (כריכה 56px, שם כקישור, stepper כמות, סכום שורה, "הסרה") → אזור מידע (פס משלוח חינם + תאריך משוער) → Footer קבוע: סכום ביניים + שני כפתורים.

### רכיבים
`MiniCart` על `Drawer` הקיים (לכידת פוקוס, Esc ורקע כבר שם), `QuantityStepper` (מיוצא מ־`MiniCart`), `FreeShippingBar`, `BookCover`, `CartProvider` (מצב `miniCartOpen`). רוחב מקסימלי `26rem`.

### פעולות
שינוי כמות (± עד `availableQuantity`), הסרה, ניווט לספר (סוגר את המגירה), "לצפייה בסל", "מעבר לתשלום" (מוצג רק כש־`checkoutEnabled`). פתיחה: מלחיצת המונה בכותרת; אחרי הוספה מעמוד ספר מותר לפתוח אוטומטית — בקטלוג Toast בלבד (פרק 6.3).

### מובייל מול דסקטופ
דסקטופ: מגירת צד מה־end. מובייל: מלוא הרוחב מלמטה (יעד פרק 6.3; ה־Drawer הקיים תומך). ה־Footer תמיד גלוי — הרשימה היא שגוללת.

### RTL
המגירה נפתחת מהצד הלוגי הנכון (`Drawer` לוגי); סכומים `tabular-nums`; מינוס/פלוס ב־stepper הם תווים, לא אייקונים כיווניים.

### מצבים
- **ריק:** "הסל ריק בינתיים" + כפתור "לקטלוג הספרים"; אין Footer.
- **Loading:** עד תשובת `getCartView` — הסכומים האחרונים שהוצגו נשארים; שורות ללא view מציגות שם+כמות בלבד (אין skeleton קופץ).
- **פריט שאזל:** השורה נשארת עם "אזל מהמלאי — הוסר מהחישוב" (או "אינו זמין עוד לרכישה") + כפתור הסרה — לעולם לא נעלמת בשקט.
- **Error/Offline:** כשל `getCartView` — הסכום הישן נשאר; הניסיון הבא (debounce 250ms) מעדכן. **Success:** עדכון סכום מוכרז ב־aria-live.
- **חנות כבויה:** הרכיב אינו מרונדר.

### טקסטים
"סל הקניות", "סגירת הסל", "הסל ריק בינתיים", "לקטלוג הספרים", "סכום ביניים", "לצפייה בסל", "מעבר לתשלום", "הסרה", "עוד {amount} למשלוח חינם" / "הגעתם למשלוח חינם 🎉", "יגיע עד {date}", "אזל מהמלאי — הוסר מהחישוב", "אינו זמין עוד לרכישה", aria: "כמות עבור {title}", "הוספת עותק", "הפחתת עותק".

### דביקות וגלילה
המגירה נועלת את גלילת ה־body; תוכן ארוך גולל בתוך המגירה בלבד; ה־Footer דביק לתחתית המגירה.

### נגישות ומקלדת
Focus trap מלא (Drawer); Esc סוגר ומחזיר פוקוס לפותח; כפתור הסגירה ראשון בסדר הטאבים; הכמות ב־`aria-live="polite"`; ה־stepper הוא `role="group"` עם תווית; פס ההתקדמות `role="progressbar"` עם `aria-valuenow`.

### אנליטיקה
`cart_viewed` (בכל פתיחה), `cart_updated` (שינוי כמות), `free_shipping_progress_shown` (חד־פעמי לכל session).

### קריטריוני קבלה
1. פתיחת המגירה < 150ms (פרק 22) — התוכן מהמצב המקומי, אימות השרת אינו חוסם רינדור.
2. סבב מקלדת מלא: Tab נשאר בתוך המגירה; Esc סוגר ומחזיר פוקוס לאלמנט הפותח (נבדק ב־E2E נגישות).
3. שינוי כמות מעדכן סכום שורה וסכום ביניים מאותה תשובת שרת — לעולם לא חישוב מקומי (ביקורת: אין אריתמטיקת מחירים ב־`MiniCart`).
4. פריט שאזל מוצג עם ההודעה ואינו נכלל בסכום; אינו מוסר אוטומטית.
5. ה־stepper לא מאפשר לחרוג מ־`availableQuantity` — כפתור ה"+" disabled בגבול.

### מבנה והיררכיה
`PageHeader` "סל הקניות" → רשת שני טורים: טור הפריטים (הודעת שינויים בראשו, `role="status"`) וטור הסיכום (aside דביק). מתחת לרשימה: "המשך עיון בקטלוג" ו"ריקון הסל".

### רכיבים
עמוד `cart/page.tsx` (מסגרת, ISR 60) + `CartPageClient` (התוכן חי בלקוח — העגלה מקומית), `QuantityStepper`, `FreeShippingBar`, `BookCover`. «חדש 1.1»: `CartCouponField` — אותו שדה קופון של ה־Checkout (`applyCoupon`/`removeCoupon` מ־`checkout-actions`), מוצג בתוך כרטיס הסיכום כשהדגל `coupons_enabled` פעיל.

### דביקות וגלילה
הסיכום דביק בדסקטופ בלבד; שמירת מיקום גלילה בחזרה מהעמוד (התנהגות הדפדפן — אין scroll-jacking); הודעת השינויים אינה נעלמת אוטומטית.

### נגישות ומקלדת
הודעת השינויים `role="status"`; אישור הריקון נגיש (window.confirm — מקלדת מלאה); שדה הקופון עם label נראה, שגיאה ב־`role="alert"` + `aria-describedby`; סדר טאבים: פריטים → קישורים תחתונים → סיכום → קופון → כפתור תשלום.

### אנליטיקה
`cart_viewed` (טעינת העמוד), `cart_updated`, `free_shipping_progress_shown`, «1.1» `coupon_applied` (גם מהעגלה — עם `meta.source='cart'`).

### קריטריוני קבלה
1. LCP עמוד העגלה < 2.5s מובייל (פרק 22).
2. הפער בין "סה״כ משוער" בעגלה לסכום בסקירת ה־Checkout ≤ דיוק הערכת המשלוח (E2E, פרק 3.3) — כולל כשקופון הוזן בעגלה.
3. קופון שהוזן בעגלה מופיע אוטומטית ב־Checkout כקופון פעיל, בלי הזנה חוזרת; הסרתו בעגלה מעדכנת את הסיכום באותו רינדור.
4. כל שינוי מחיר/כמות/זמינות שהתגלה באימות מוצג בבאנר במילים — אפס עדכונים שקטים (E2E 16).
5. אין חישוב מחיר בצד הלקוח: הסכום היחיד שמחושב ברכיב הוא חיבור תצוגה של ערכי שרת (ביקורת קוד).
6. במובייל אין טבלה/גלילה אופקית; כל שורת פריט נשלטת במקלדת בלבד.

### מבנה והיררכיה
כותרת "השלמת הזמנה" → "← חזרה לסל" → רצועת אקספרס (אם `expressEnabled`) → שלושה בלוקים ממוספרים ב־progressive disclosure: פתוח אחד בכל רגע; בלוק שהושלם מציג ✓ + תקציר + "עריכה"; בלוק שטרם הגיע תורו ב־opacity 60% ואינו לחיץ. הסיכום aside דביק (במובייל — ראשון, מעל הבלוקים: `order-first`).

### רכיבים
`CheckoutClient` (תיאום, session, placeOrder), `BlockShell` (מעטפת בלוק: מספר/✓, "עריכה"), `ContactBlock` (+`Field` המשותף), `FulfillmentBlock`, `ReviewBlock`, `ExpressStrip`, פעולות שרת `checkout-actions` (`startCheckout`, `saveContact`, `saveFulfillment`, `applyCoupon`, `saveExtras`, `placeOrder`).

### פעולות
- **בלוק 1:** טלפון (ראשון, חובה) → שם → מייל (חובה) → "המשך". שורת "אין לכם דואר אלקטרוני? נשמח לקבל את ההזמנה בטלפון: {phone}".
- **בלוק 2:** בחירת שיטה (רדיו־כרטיסים שווי־ערך, מחיר + "יגיע עד {date}" לכל שיטה); משלוח → טופס כתובת ישראלי מלא + "הערות לשליח"; איסוף → כתובת, שעות, "נעדכן אתכם ברגע שההזמנה מוכנה לאיסוף".
- **בלוק 3:** קופון (אם לא הוזן בעגלה — «1.1»), "זו מתנה 🎁" (נמען, הקדשה ≤300 תווים, "להסתיר את המחיר מהחבילה" מסומן כברירת מחדל), ערוץ נייד (ריק כברירת מחדל), תשלומים ("או עד {n} תשלומים…"), תקנון (לא מסומן מראש) + תמצית ביטול, כפתור התשלום.
- **אקספרס:** בחירת ארנק נרשמת על ה־session (`aria-pressed`); Apple Pay מוצג רק כש־`ApplePaySession.canMakePayments()`.
- **placeOrder:** נעילת כפתור + "יוצר הזמנה מאובטחת…"; הצלחה → ריקון הסל → redirect למורנינג או `/checkout/result?outcome=created`.

### מובייל מול דסקטופ
דסקטופ: `1fr_20rem`, סיכום דביק `top-28`. מובייל: הסיכום ראשון (מתקפל רעיונית — כיום מוצג מלא), בלוקים נערמים, מקלדות ייעודיות (`inputmode=tel/email/numeric`), כפתורי האקספרס בבולטות מלאה.

### RTL
`dir="ltr"` על: טלפון, מייל, מיקוד, קוד קופון; שאר הטופס לוגי. שמות הארנקים (bit/Google Pay) נשארים לטיניים.

### מצבים
- **חנות/קופה כבויה:** "החנות אינה פעילה כרגע." (בשרת — לפני רינדור הטופס).
- **סל ריק:** "הסל ריק בינתיים" + "לקטלוג הספרים".
- **Loading:** שלושה מלבני skeleton עד תום `startCheckout`. רענון משחזר את הבלוקים שהושלמו מה־session (חוזרים סגורים עם ✓).
- **שגיאות שדה:** "שדה חובה" / "מספר טלפון ישראלי תקין נדרש" / "כתובת דואר אלקטרוני תקינה נדרשת".
- **שגיאות הזמנה (באנר `role="alert"`):** "הסכום התעדכן ל-{total} — בדקו את הסיכום ואשרו שוב" (הסכום החדש מוצג בסיכום — אישור מחדש נדרש, פרק 7.6), "אחד הספרים אזל בינתיים. הסל עודכן — בדקו אותו שוב.", "הפריטים שבסל אינם זמינים עוד לרכישה.", "יותר מדי ניסיונות. המתינו רגע ונסו שוב.", "משהו השתבש. נסו שוב או הזמינו בטלפון."
- **payments כבוי:** הכפתור "שליחת ההזמנה" + "נחזור אליכם טלפונית להסדרת התשלום." **Offline:** ה־session בצד השרת שורד; שליחה נכשלת עם errServer וניתן לנסות שוב.

### טקסטים
כל המחרוזות קיימות ב־`store` (מצוטטות לעיל ובקוד): "פרטי התקשרות", "אספקה", "סיכום ואישור", "טלפון נייד", "שם מלא", "דואר אלקטרוני", "לכאן נשלח אישור ההזמנה והחשבונית", "המשך", "עריכה", "חינם", "זו מתנה 🎁", "שם מקבל המתנה", "הקדשה אישית (רשות)", "להסתיר את המחיר מהחבילה", "החשבונית נשלחת אליכם בלבד, לא לנמען.", "רוצה גם עדכון מהיר לנייד?", "בהודעת SMS", "בוואטסאפ", "או עד {n} תשלומים ללא ריבית באשראי", "קראתי ואני מסכימ/ה ל" + "תקנון ולמדיניות הביטול", "ניתן לבטל תוך 14 יום ממסירה, פרטים בתקנון.", "מעבר לתשלום מאובטח", "יוצר הזמנה מאובטחת…", "התשלום מתבצע בדף מאובטח של מורנינג (חשבונית ירוקה).", "מעדיפים להזמין בטלפון? נשמח לעזור: {phone}", "תשלום מהיר", "או מילוי פרטים רגיל".

### דביקות וגלילה

### נגישות ומקלדת

### אנליטיקה

### קריטריוני קבלה
1. השלמת מסלול רגיל במובייל < 90 שניות (E2E מתוזמן, פרק 22); TTI < 3s.
2. אפס מסכי הרשמה/סיסמה בנתיב; שדה הטלפון ראשון ב־DOM (בדיקת snapshot).
3. לחיצה כפולה / רענון / Back / לשונית שנייה — הזמנה אחת בלבד (idempotency, E2E; פרק 7.4).

5. תיבת התקנון לא מסומנת מראש; שליחה בלעדיה מציגה "יש לאשר את התקנון כדי להמשיך" ומעבירה פוקוס לשגיאה.
6. סבב מקלדת מלא על שלושת הבלוקים כולל עריכת בלוק סגור; ציון Axe ללא הפרות ברמה A/AA.

### מבנה והיררכיה
עמוד ממורכז, טור צר: עיגול אייקון (✓ / ! / ⟳ / ⋯) → כותרת → פסקת גוף → תוכן נוסף (תאריך, הצעת חשבון, כפתור ניסיון חוזר) → "חזרה לקטלוג". הכל בתוך `role="status" aria-live="polite"`.

### רכיבים
`ResultClient` + `getResultState` (polling כל 3 שניות, עד 20 ניסיונות ≈ דקה); עמוד `checkout/result/page.tsx` (`force-dynamic`, `robots: noindex`). מקור האמת — השרת לפי ה־session; פרמטר ה־URL (`outcome`) לעולם אינו קובע לבדו (פרק 7.5).

### פעולות
- **מעבדים:** אין פעולה — רענון אוטומטי; אחרי דקה ללא הכרעה → מצב "לא ידוע".
- **הצלחה:** הצעת החשבון הפסיבי — "פתיחת חשבון בקליק" → `/account/login`; זו ההצעה הממוקדת היחידה (פרק 3.8 — בלי קרוסלות).
- **כשל:** "ניסיון תשלום חוזר" → `/checkout` (אותה הזמנה ממוחזרת — אין חיוב כפול); טלפון עזרה.
- **לא ידוע / עוגייה פגה:** הודעה ניטרלית — המייל הוא המקור.

- **מעבדים (pending):** "מעבדים את התשלום…" + spinner — **אינו שגיאה** (תרשים 19).

### דביקות וגלילה

1. מוזמן חדש מקבל מייל עם סיסמה ראשונית, נדרש להחליפה בכניסה הראשונה, ורואה רק את המסכים של תפקידו (E2E הרשאות).
2. מלקט אינו רואה סכומי תשלום/זיכוי ואינו יכול לבצע פעולה כספית — נאכף גם ב־UI וגם בשרת (assertRole/RLS).
3. מוכרן יוצר הזמנה טלפונית ושולח קישור תשלום, אך כפתורי הזיכוי ו"סימון תשלום חיצוני" אינם קיימים עבורו ב־DOM.
4. אי־אפשר להשהות/להוריד את מנהל־העל האחרון — הפעולה חסומה עם הודעה.
5. כל שינוי תפקיד מופיע ב־audit עם old/new ומבצע; הזמנת לקוח (מסך 7) לעולם אינה יוצרת שורת profiles (E2E 14).
