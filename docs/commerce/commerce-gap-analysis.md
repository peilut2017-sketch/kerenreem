## 0. **[1.1]** מצב לאחר סבבי הבנייה — מה נבנה ומה נשאר

> סעיפים 1–3 שלהלן הם ניתוח הבסיס המקורי — צילום מצב **לפני** הבנייה, שנשמר כתיעוד הנימוקים. הסעיף הזה הוא המצב העדכני: סבבי הבנייה מימשו את שלבי התוכנית 1–10 בקוד, על הענף הזה. שימו לב להבחנה: **"נבנה" ≠ "פועל בייצור"** — ההפעלה כפופה לאימותי Sandbox, למפתחות ייצור, לשער G1–G6 ולתנאי פרק 26.

### 0.2 מה נשאר (ברמה גבוהה)

> **עדכון: סבב בנייה 1.1 בוצע.** ‏B1–B12 ו-B14 נבנו (migration ‎36, ‏HMAC, זרימת ביטול מתוקנת, ‏Claim בטוח, צמצום Payload, מסך צוות + חמשת התפקידים, ניווט "חנות", מועדפים-כספר + עמוד ציבורי + אייקוני כותרת, קופון בעגלה + צבירה, ריבוי מחסנים, עלויות ורווחיות, התאמה יומית) + רענון עיצובי לעגלה ולאדמין — פירוט מלא ב[יומן השינויים](./commerce-changelog.md). מה שנשאר:

1. **הפעלה ואימות מול העולם האמיתי (שלב 0 + פרק 26):** חתימה מול מורנינג, ‏Sandbox, אימותי A1–A14, מפתחות ב־Vercel (כולל `SUPABASE_SERVICE_ROLE_KEY` — בלעדיו פעולות מלאי/הזמנות מדווחות "אין חיבור למסד", ו־`COMMERCE_HMAC_SECRET` החדש), הרצת `36_v11_corrections.sql` ב-Supabase, ‏Resend + אימות דומיין, עסקת אמת, תנאי הפתיחה 1–24.
2. **‏B13:** מצב "לכידה באריזה" — ממתין לאימותי A13/A14 מול מורנינג.
3. **שער לפני־תשלום (G1–G6):** קיים בקוד; נדרש אימות בפעולה מול Sandbox (G3 רץ רק עם מפתחות מורנינג).
4. **עתידי מתוכנן:** ‏SMS/וואטסאפ (כנראה "ימות המשיח"), השלמת עיר/רחוב, מבצעים אוטומטיים, צבירת שני קופונים צבירים בפועל (עם מנוע ה-promotions), "נקנו יחד", ‏PITR.
5. **ירד מהתכולה:** תרומות (החלטה 20).
