# מכון קרן רא״ם — אתר וקטלוג ספרים

אתר תוכן דו-לשוני עם קטלוג ספרים ומערכת ניהול תוכן, בנוי על Next.js ו-Supabase.

- **שלב א' (מומש):** קטלוג ספרים, עמודי מחברים, פעילות, אירועים, עמודי חובה חוקיים, CMS מלא, תאריכים עבריים, תשתית דו-לשונית.
- **שלב ב' (מוכן בסכימה, כבוי):** חנות — עגלה, צ'ק-אאוט וסליקה. השדות והטבלאות קיימים; ההפעלה היא דגל.

---

## סטאק

| שכבה | טכנולוגיה |

## הרצה מקומית

```bash
npm install
cp .env.example .env.local     # ומלאו את הערכים
npm run dev                    # http://localhost:3000
```

האתר עולה ונבנה **גם בלי חיבור ל-Supabase**. במצב כזה שכבת הנתונים מחזירה
תוצאות ריקות, העמודים מציגים מצבי ריק, וממשק הניהול מסביר אילו משתני סביבה
חסרים. זה מכוון: מפתח חדש או בנייה ב-CI לא אמורים להיחסם על גישה למסד.

הם כלי תיקון. ראו "תקלות נפוצות" למטה.

> ⚠ **אם אתם מריצים `drop schema public cascade` כדי להתחיל מחדש** — חובה
> להריץ אחריו את `06_restore_grants.sql`. הפקודה מוחקת יחד עם הסכימה גם את
> הרשאות התפקידים `anon` ו-`authenticated`, שדרכם האתר ניגש למסד, ויצירת
> הסכימה מחדש אינה מחזירה אותן. בלי זה האתר מקבל `permission denied` על כל
> טבלה — בעוד שב-SQL Editor הכל נראה תקין, כי הוא רץ בתפקיד `postgres`.

> `01_schema.sql` ו-`03_seed.sql` הם הקבצים שנמסרו, ללא שינוי. כל מה שנוסף
> בזמן בניית האתר יושב בקבצים 2 ו-4 בנפרד, כדי שההפרדה תישאר ברורה.

### יצירת המשתמש הראשון

1. ב-Supabase → Authentication → Users → הוסיפו משתמש (דואר וסיסמה).
2. הפכו אותו למנהל:
   ```sql
   update profiles set role = 'admin', full_name = 'שם מלא'
   where id = '<user-uuid>';
   ```
3. היכנסו ל-`/admin/login`. משתמשים נוספים נוצרים ב-Supabase, והתפקיד שלהם
   נקבע במסך **הגדרות**.

### תפקידים

| תפקיד | יכולות |
|-------|--------|
| `admin` | הכל — הגדרות אתר, דגלי פיצ'ר, ניהול צוות |
| `editor` | יצירה ועריכה של ספרים, מחברים, אירועים, פעילות ועמודים; קריאת פניות |
| `viewer` | צפייה בלבד |

ההרשאות נאכפות בשלוש שכבות: ה-proxy חוסם גישה ל-`/admin` בלי session, כל
Server Action בודק תפקיד לפני כתיבה, ו-RLS במסד חוסם גם קריאה ישירה ל-API.

## תקלות נפוצות

### התחברות מצליחה אבל חוזרת מיד למסך ההתחברות

המשתמש מאומת מול Supabase Auth, אבל אין לו שורה בטבלת `profiles` — ולכן
אין לו תפקיד ואין לו הרשאה לשום מסך.

זה קורה כש-`profiles` נוצרה מחדש אחרי שהמשתמש כבר היה קיים: `auth.users`
חיה בסכימת `auth` ושורדת גם `drop schema public cascade`, בעוד `profiles`
נמחקת ונוצרת ריקה. הטריגר `on_auth_user_created` פועל רק ביצירת משתמש
חדש ולכן לא ירוץ עליהם שוב.

האתר מזהה את המצב ומציג במסך ההתחברות הסבר עם פקודת ה-SQL לתיקון, במקום
להחזיר לטופס בלולאה. התיקון המלא נמצא ב-`supabase/05_repair_profiles.sql`.

### `permission denied` / הקטלוג ריק / "אין למשתמש פרופיל" למרות שהפרופיל קיים

התפקידים `anon` ו-`authenticated` איבדו את הרשאות הגישה לסכימת `public`.
קורה אחרי `drop schema public cascade`. הנתונים קיימים ונראים תקין ב-SQL
Editor (שרץ כ-`postgres`), אבל האתר חסום.

הריצו את `supabase/06_restore_grants.sql` — הוא כולל שאילתת אבחון שמראה
לכל טבלה אם לתפקידי האתר יש הרשאת קריאה.

RLS אינו מושפע: ההרשאות פותחות את הדלת לטבלה, ומדיניות ה-RLS ממשיכה
לקבוע אילו שורות נראות.

### Supabase מחזיר `missing email or phone`

תוקן. הסיבה הייתה שדות controlled: מנהל סיסמאות מציב `value` ישירות על
ה-DOM בלי אירוע ש-React מזהה, ולכן ה-state נשאר ריק בעוד שהשדה נראה מלא.
הטופס קורא היום מ-`FormData`. `npm run check:login` מאמת את שני התרחישים.

### `relation "public.profiles" does not exist` בהרצת הסכימה

תוקן ב-`01_schema.sql`: פונקציות ההרשאה הועברו לסעיף 4.1א, אחרי הטבלה
שהן קוראות ממנה. ודאו שאתם על הגרסה העדכנית מ-git.

## מבנה הפרויקט

```
src/
  app/
    (public)/[locale]/     האתר הציבורי — root layout משלו, RTL/LTR לפי שפה
    (admin)/admin/         ממשק הניהול — root layout נפרד, עברית בלבד
    sitemap.ts robots.ts icon.svg
  components/              רכיבי האתר הציבורי
  components/admin/        רכיבי ה-CMS (טפסים, שדות, עורך)
  lib/
    data.ts                שליפות ציבוריות (רק תוכן שפורסם)
    hebrew-date.ts         המרות לוח עברי
    sanitize.ts            ניקוי HTML + allowlist להטמעות
    localized.ts           בחירת שדה _he/_en עם נפילה לעברית
    supabase/              לקוחות וטיפוסים
    admin/                 הרשאות, שליפות ניהול, Server Actions
  i18n/  messages/         ניתוב שפה ומחרוזות ממשק
supabase/                  SQL להרצה
scripts/                   בדיקות שפיות (תאריכים, נגישות)
```

### שתי החלטות מבניות ששווה להכיר

**שני root layouts.** האתר הציבורי וממשק הניהול הם route groups נפרדים, כל
אחד עם `<html>` משלו. הניהול עברי בלבד ואינו עובר דרך ניתוב השפות, ולכן
`/admin` אינו מקבל קידומת שפה.

**הסכימה קובעת מה נשמר.** `src/lib/admin/schema.ts` מגדיר לכל ישות את
רשימת השדות הניתנים לכתיבה. שדה שאינו ברשימה לא ייכתב למסד גם אם יישלח
בטופס — הגנה מפני mass assignment. הוספת שדה חדש = שורה בקובץ הזה + שדה
בטופס.

### אבחון תקלות שמירה

`/admin/diagnostics` (Admin בלבד) מבצע קריאה מכל טבלה, **ניסיון כתיבה
אמיתי** (הוספה ומחיקה מיידית), ובדיקת קיום ה-buckets — ומדווח את קוד
השגיאה המדויק של Postgres עם המשמעות שלו. זו הדרך המהירה להבחין בין
טבלה חסרה, הרשאה חסרה, ומדיניות RLS.

### עמודים בעלי `slug` שמור

האתר מחפש עמודים לפי מזהה כתובת. שינוי המזהה מנתק את העמוד:

`home` (משפט הפתיחה) · `about` · `donate` · `terms` · `privacy` · `accessibility`

מסך העריכה מתריע כשעורכים אחד מהם.

### הטמעת וידאו

בעורך התוכן ובשדה "סרטון ראשי". מותרים YouTube ו-Vimeo בלבד — הרשימה

## נגישות

האתר נבנה נגיש מהיסוד — HTML סמנטי, תווית לכל שדה, שגיאות מקושרות
ב-`aria-describedby`, ניווט מקלדת מלא, וסימון מיקוד נראה. סרגל הנגישות
הצף הוא שכבת התאמה **מעל** בסיס נגיש, לא במקומו.

```bash
npm run build && npm start &
npm run check:a11y          # axe-core (WCAG 2.1 AA) על כל העמודים, בשני רוחבי מסך
npm run check:a11y-toolbar  # בדיקה תפקודית לסרגל הנגישות
```

הבדיקה כוללת גם את הרכיבים האינטראקטיביים במצב פתוח — סרגל הנגישות
והתפריט הנייד — שסריקה רגילה לעולם לא מגיעה אליהם.

> ⚠ בדיקה אוטומטית מזהה כ-30%–40% מכשלי הנגישות. לעמידה בתקן 5568 נדרשת
> גם בדיקה ידנית עם קורא מסך ובניווט מקלדת בלבד. הבדיקה האוטומטית רצה
> נקייה על העמודים כפי שהם — אך עם מילוי הקטלוג יש להריץ שוב, כי תוכן
> אמיתי (תמונות, טקסט עשיר) מביא איתו סיכוני נגישות חדשים.

## אבטחה

- כותרות אבטחה (CSP, HSTS, X-Frame-Options ועוד) מוגדרות ב-`next.config.ts`.
  ה-CSP מתיר `unsafe-inline` לסקריפטים כי Next מזריק סקריפטים מוטבעים;
  הידוק ל-nonce הוא שדרוג ראוי בהמשך.
- כל HTML מהעורך עובר sanitize **פעמיים** — בשמירה למסד ובתצוגה.
- `SUPABASE_SERVICE_ROLE_KEY` עוקף RLS. שרת בלבד, לעולם לא עם קידומת
  `NEXT_PUBLIC_`.
- טופס יצירת הקשר מוגן במלכודת בוט, בהגבלת קצב בזיכרון התהליך (חלקית —
  ראו ההערה ב-`contact/actions.ts`), ובהגבלות אורך ברמת המסד. קאפצ'ה
  (reCAPTCHA v2) זמינה כתוספת מוגדרת-תצורה: מוצגת ונאכפת רק כש-
  `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` ו-`RECAPTCHA_SECRET_KEY` מוגדרים
  (ראו `.env.example`) — בלעדיהם הטופס ממשיך לעבוד כרגיל, בלי הרחבת CSP.
- קבצים מצורפים לפנייה נשמרים ב-bucket פרטי (`contact-attachments`, לא
  ציבורי כמו שאר האחסון באתר) — נגישים רק לצוות מחובר עם הרשאת עריכה,
  דרך קישור חתום שנוצר לפי דרישה. גודל וסוג הקובץ נאכפים גם ברמת
  ה-bucket עצמו (`20_contact_attachments.sql`), לא רק בטופס.

## הפעלת החנות (שלב ב')

הסכימה כבר מכילה `orders`, `order_items`, ואת שדות המסחר ב-`books`. עמוד
הספר בנוי כך שההבדל היחיד בין קטלוג לחנות הוא רכיב אחד
(`BookPurchase`), המותנה בשני תנאים: הדגל הגלובלי `store_enabled`
ו-`is_purchasable` ברמת הספר.

לפני הפעלת הדגל:

1. לחבר ספק סליקה ישראלי (Cardcom / Tranzila / Grow) דרך Route Handlers
   בצד השרת. האתר לא נוגע בפרטי אשראי — כך הוא נשאר מחוץ להיקף PCI.
2. לעדכן את סעיף 7 בתקנון בתנאי רכישה, אספקה, ביטול והחזרים לפי חוק
   הגנת הצרכן.
3. להוסיף את ספק הסליקה לרשימת הצדדים השלישיים במדיניות הפרטיות.
4. להשלים עגלה, צ'ק-אאוט ואזור לקוח.

הרשימה המלאה, לפי עדיפות, נמצאת בסוף `supabase/04_seed_legal.sql`.
בקצרה:

1. **קריטי** — למלא כל `[למילוי: ...]` בשלושת המסמכים המשפטיים.
2. **קריטי** — להזין בהגדרות: מספר עמותה, ממונה פרטיות, רכז נגישות.

4. **גבוה** — אישור עורך דין לשלושת המסמכים.
5. **גבוה** — MFA לחשבונות הניהול ב-Supabase.

   ולא צבעים קשיחים.

## עיצוב

הפלטה נדגמה מן הלוגו: הזהב החם של הספר הפתוח (`#c8a868`), השחור של
הכיתוב, והנייר הבהיר שמסביב. הכחול העמוק (`#0b1520`) נלקח מתרשים העיצוב
ומשמש לרצועות הכהות — קרוסלת הפתיחה, יצירת קשר, והתחתית.

### כללי הזהב

- **זהב הוא קו, לא שטח.** קווי הפרדה, העיטור מתחת לכותרת, וקישורי המשך.
  לעולם לא כרקע גדול.
- **זהב על נייר אינו עומד ביחס ניגודיות לטקסט** (2.1:1). לכן על רקע בהיר
  הוא דקורטיבי בלבד, ולטקסט משתמשים ב-`--color-gold-deep`. על הכחול
  העמוק היחס 7:1 והזהב כשר לטקסט.
- שני משקלי כפתור, שתי משפחות גופנים, פינות כמעט ישרות, בלי צללים כבדים.

### מוטיבים חוזרים

| רכיב | מתי |
|------|-----|
| `<Ornament />` | קו—מעוין—קו בזהב, בפתיחת מקטע מרכזי בלבד |
| `.link-more` | קישור המשך עם חץ שנע במעבר עכבר |
| `<Reveal>` | הופעה עדינה בגלילה, פעם אחת |
| `.on-dark` | רצועה כהה. הווריאנט `on-dark:` מתאים רכיב לשני הרקעים |

### תנועה

`<Reveal>` מסתיר תוכן רק אחרי ש-JS הוסיף `js` ל-`<html>`, כך שדפדפן בלי
סקריפטים מקבל עמוד מלא. `prefers-reduced-motion` מבטל את ההסתרה לגמרי,
וסרגל הנגישות מאפשר עצירה יזומה.

הקרוסלה עומדת ב-WCAG 2.2.2: כפתור השהיה, עצירה במעבר עכבר ובמיקוד
מקלדת, חצים במקלדת, וכיבוי מלא תחת `prefers-reduced-motion`. השקופיות
נבנות מתוכן אמיתי בלבד — ספר, אירוע וציר פעילות — ולא מתמונות מלאי.

## תצוגה מקדימה ללא מסד

```bash
NEXT_PUBLIC_DEMO_CONTENT=1 npm run dev
```

מציג את האתר עם תוכן לדוגמה (`src/lib/demo-content.ts`) וכריכות/צילומים
מסומנים תחת `public/demo`. פועל **רק** כשאין `NEXT_PUBLIC_SUPABASE_URL`,
כך שבסביבה אמיתית הקוד הזה לעולם אינו רץ. שימושי לסקירת עיצוב ולפיתוח
ממשק בלי גישה למסד.

```bash
npm run build && ./scripts/serve.sh 3000
node scripts/shots.mjs http://localhost:3000 /tmp/shots   # צילומי מסך
```

> ⚠ הקבצים ב-`public/demo` הם מצייני מקום מסומנים, לא תמונות מלאי. אין
> להשתמש בהם באתר החי — הכריכות והצילומים האמיתיים נטענים דרך ה-CMS.
